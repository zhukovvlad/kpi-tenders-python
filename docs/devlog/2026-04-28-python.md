## Решения и обоснования

**Кастомный lifecycle для `resolve_keys`** — задача не скачивает никаких файлов. Все входные данные приходят через `kwargs` из Go. Использование `run_document_task` было бы лишним (оно всегда делает `minio.download()`). Написан отдельный `_run_resolve_keys()` с теми же гарантиями (processing → completed/failed, retry).

**Closure-паттерн для `extract`** — `_handle()` нужен доступ к `extraction_schema` из kwargs, но `run_document_task` ожидает `handler(file_bytes, storage_path, minio)`. Решение: `_bound_handle = lambda file_bytes, sp, minio: _handle(file_bytes, sp, minio, extraction_schema)`. Это позволяет переиспользовать готовый `run_document_task` без изменения его сигнатуры.

**`Optional[str]` для всех полей extract** — суммы в русских договорах ("1 500 000 руб. с НДС") нельзя надёжно парсить во float. Go хранит всё как текст в `document_extracted_data.value`. Gemini может вернуть `null` если значение не найдено — Python оставляет как `None`, Go пропускает при сохранении.

**Удаление `md_document_id` из `resolve_keys`** — изначально Python принимал `md_document_id` как обязательный kwarg, никак не использовал в LLM-логике и возвращал обратно в `result_payload`. Это чистый pass-through антипаттерн: Go сам знает, к какому документу относится задача — ему не нужен Python как зеркало. После удаления:
- Go больше не должен делать `ListDocumentsByParent` перед публикацией `resolve_keys_task`
- Kwargs: только `raw_questions: list[str]` и `existing_keys: list[dict]`
- `result_payload`: только `{"new_keys": [...], "resolved_schema": [...]}`
- Убрано 2 теста-валидации для `md_document_id`, добавлен `test_result_has_no_md_document_id`

## Ловушки и особенности

**`.run()` у bind=True задач Celery** — Celery уже привязывает `self` в `.run()`, поэтому в тестах нужно вызывать `task.run(task_id, doc_id, storage_path, **kwargs)` без явного `self`. `.__wrapped__` не работает с `**kwargs` (принимает фиксированный список аргументов).

**`GeminiAPIError` наследует `ValueError`** — поэтому попадает в `_NO_RETRY = (GoClientError, GeminiAPIError, ...)` без дополнительной логики. `ValueError` из валидации kwargs тоже не ретраится (тот же тип), что правильно: неверные kwargs — это ошибка Go, ретрай бессмысленен.

**`str | None` вместо `Optional[str]`** — Python 3.12 поддерживает union-синтаксис нативно. `Optional[str]` — это алиас из `typing`, который ruff (UP045) помечает как устаревший. `_FIELD_TYPE` в `extract_llm.py` теперь использует `str | None` напрямую. `from typing import Optional` удалён.

**Валидация `extraction_schema` в `_build_extraction_model()`** — если Go пришлёт `[{}]` или `["string"]`, Python словит `KeyError`, который не входит в `_NO_RETRY` и уйдёт в 3 ретрая вместо быстрого провала. Добавлена явная валидация с `ValueError` (входит в `_NO_RETRY`): проверка что entry — dict, что `key_name` — непустая строка. Это системная граница (данные от другого сервиса).

**`make ci`** — добавлена цель `format → check → test`. `format` идёт первым, потому что ruff format может исправить то, что `check --fix` не трогает (пробелы, переносы). `check` после этого проверяет без записи. Использовать перед `git push`.
