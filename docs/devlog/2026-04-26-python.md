## Решения и обоснования

**Почему 5xx от Go не должен быть `_NO_RETRY`.**

До этого `GoClientError` покрывал и 4xx, и 5xx. Оба типа попадали в `_NO_RETRY` — задача ронялась без повтора. Логика неверная: 4xx означает баг (неверный токен, неверный формат) — ретраить бессмысленно. 5xx означает что Go временно недоступен — Celery должен вернуть задачу в очередь.

После разделения: `GoServerError` (5xx) **не** в `_NO_RETRY` → падает в ветку `task.retry(exc=exc)` → 3 попытки с backoff 30с.

**Почему `GoServerError` не нужно импортировать в `base.py`.**

Исключение просто не перехватывается `isinstance(exc, _NO_RETRY)` — оно проваливается дальше в `raise task.retry(exc=exc)`. Для этого импорт не нужен; импорт только `GoClientError` достаточен. Ruff ловил бы неиспользуемый импорт как F401.

**Реальная застрявшая задача — почему именно `pending`, а не `processing`.**

Воркер принял задачу из Redis (BRPOP), но первый же PATCH (`status = processing`) вернул 401. `GoClientError` → `_NO_RETRY` → задача ACK'нута из Redis. Статус в Go БД не успел смениться — остался `pending`. Go-watchdog смотрит только на `processing` → задача невидима для watchdog.

Это отдельный gap на стороне Go: watchdog должен покрывать `IN ('pending', 'processing')`.

## Ловушки и особенности

**`SERVICE_TOKEN` в `.env` — молчаливый дефолт.**

Python-репо `.env` содержал `change-me-service-token` (скопирован из `.env.example`). Go-репо имел реальный токен. При старте никакой ошибки — воркер запускается нормально, `SERVICE_TOKEN` читается без жалоб. Первый симптом — 401 при реальной задаче.

Обнаружили сравнив `grep SERVICE_TOKEN` в обоих `.env`. Оба файла в `.gitignore`, токен в публичный git не попал.

**Celery ACK при 4xx = потеря задачи.**

`task_acks_late=True` ackует задачу при завершении (в том числе при исключении, которое не в `_NO_RETRY`). Если обработчик бросил `GoClientError` (включая 401) — задача ACK'нута и исчезает из Redis навсегда. Это ожидаемое поведение для 4xx (баг конфигурации, повтор не поможет), но важно понимать что задача теряется до тех пор пока watchdog не вернёт её.

**Watchdog на Go покрывает только `processing`.**

Обнаружено при ревью `sql/query/document_task.sql`:
```sql
WHERE dt.status = 'processing'   -- pending не покрыт
  AND dt.updated_at < $1
```
Partial index в миграции `000002` тоже только на `processing`. Промт с конкретными правками передан на Go-сторону.
