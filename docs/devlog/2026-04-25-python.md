## Решения и обоснования

**Почему убрали HTTP, а не оставили как есть.**
Python API (`/process`) был прокси-слоем: принимал HTTP от Go и вызывал `apply_async`. Если воркеры недоступны — это нормально (Celery держит очередь), но если сам Python API недоступен — Go не мог поставить задачу вообще. Redis видят оба сервиса, поэтому Go публикует напрямую, минуя этот лишний hop.

**`/health` остался.**
Python API не исчез полностью — он нужен для мониторинга состояния воркеров (`celery ping`). Это единственная причина держать FastAPI-процесс запущенным рядом с воркерами.

**Формат: Celery protocol v2 через LPUSH.**
Celery использует Redis-список: producer — `LPUSH`, worker — `BRPOP`. Сообщение — JSON с base64-кодированным `[args, kwargs, embed]` в поле `body`. Go-агент реализовал это в `internal/pythonworker/client.go`; в `headers.id` пишется Go-шный UUID задачи, что даёт сквозной трейсинг без дополнительной логики.

## Code review: правки по итогам двух раундов ревью (Copilot + CodeRabbit)

### Что зафиксировано

**`app/nlp/anonymizer.py`**

- **`_has_context` — word-boundary check.** Заменили `w in window` на `re.search(r"(?<!\w)..(?!\w)", window)`. Без этого короткие токены вроде `"кпп"` могли матчиться внутри несвязанных слов. Риск был реальным для IP-контекста (`"ip"` → `"chip"`), хотя в тендерных текстах встречается редко.

- **`BANK_ACCOUNT` grouped pattern → `needs_context=True`.** Паттерн `\b\d{5} \d{3} \d{4} \d{4} \d{4}\b` (форматированный счёт с пробелами) без контекста давал false positives на кодах бюджетной классификации. Добавили `needs_context=True` с тем же `_BANK_CONTEXT`, который вынесли в именованную константу.

- **СНИЛС fallback → Mod-101 checksum.** Заменили `re.fullmatch(r"\d{11}", ...)` на честную реализацию контрольной суммы по ГОСТ Р 54471-2011. Алгоритм: взвешенная сумма 9 цифр (веса 9..1), `control = sum % 101`, если `≥ 100` → 0. Уменьшает false positives на артикулах и других 11-значных числах.

- **`_get_pipeline()` → double-checked lock.** Добавили `threading.Lock` с двойной проверкой. Celery форкает воркеры — между процессами lock не нужен, но при `--pool=gevent/eventlet` race condition был реальным. Стоимость — одна переменная и два `if`.

**Что намеренно не стали трогать:**

- `_dedup_spans` — priority-based overlap resolution. Ревьюеры предлагали заменить greedy left-to-right на итеративный pop с приоритетом. Отклонено: частичные перекрытия с разных позиций (A=[0,5], B=[2,10]) в тендерных текстах — экзотика. Алгоритм усложнился бы без реального выигрыша; докстринг уже честно описывает текущее поведение.
